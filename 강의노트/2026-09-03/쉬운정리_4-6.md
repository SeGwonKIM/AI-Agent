# 4강. AI가 약한 곳 세 가지

## 먼저, 왜 이 이야기를 하나

바이브 코딩에는 아주 흔한 실패 패턴이 있습니다.

> **첫날** — "우와, 하루 만에 화면이 다 만들어졌어!"
> **다음 주** — "로그인이 자꾸 풀려… 저장한 게 사라져… 클라우드 요금이 왜 이렇게 나왔지?"

화면은 금방 살아나는데 그다음 벽에 부딪힙니다. 이유는 하나입니다.

> **AI는 "돌아가는 코드"는 잘 만들지만 "안전하고 튼튼한 코드"는 놓칩니다.**
> 내가 **말하지 않으면** 보안을 알아서 챙겨 주지 않습니다.

그래서 아래 세 가지는 내가 챙겨야 합니다. **문법을 외울 필요는 없고, AI에게 요구할 줄만 알면 됩니다.**

---

## ① 보안 — 가장 약한 곳

### 얼마나 약한가

보안 회사 Veracode 가 AI 모델 100개 넘게 실험했더니 **AI가 만든 코드의 약 45%에 보안 구멍**이 있었습니다. 더 놀라운 건, **모델이 똑똑해져도 이 비율이 거의 안 줄었다**는 점입니다.

> 문법은 좋아졌지만 **안전은 그대로**라는 뜻입니다.

### 가장 흔한 구멍 — "입력을 그대로 믿는 것"

검색창에 사용자가 이름을 칩니다. 보통은 "김민준"이라고 치죠.
그런데 나쁜 사람은 이름 칸에 **명령어처럼 생긴 글자**를 넣습니다.
서버가 그걸 그대로 믿고 **실행하면** 데이터가 통째로 털리거나 지워집니다.

규칙은 하나입니다.

> **"사용자가 보낸 값은 일단 의심하고 검사한다."**

### 실제로 있었던 일들

| 사고 | 언제 | 무슨 일 |
|---|---|---|
| 에퀴팩스 | 2017 | **알려진 구멍을 방치**하다 약 1억 4,300만 명의 주민번호·생일·주소 유출 |
| 소니 PSN | 2011 | 약 7,700만 명 정보 유출, 서비스가 오래 멈춤 |
| 야후 보이스 | 2012 | **비밀번호를 그대로(암호화 없이) 저장**했다가 통째로 유출 |
| 마이스페이스 | 2008 | 약 3억 6천만 계정 유출 → **같은 비밀번호 재사용의 위험** |
| MOVEit | 2023 | 파일 전송 프로그램의 허점으로 2,700개 기관·9천만 명 이상 노출 |

공통점이 보입니다 — **입력을 함부로 믿었거나, 비밀번호를 그대로 뒀거나, 알려진 구멍을 안 막았거나.** 큰 회사도 기본을 놓쳐서 뚫립니다.

### 💬 AI에게 이렇게 말하세요

> "**사용자 입력을 검증**하고, **비밀번호는 해시로 저장**하고, 모든 통신은 **HTTPS**로 해줘.
> 흔한 보안 취약점(입력값 주입, XSS)을 막아줘."

이 한 문장이 가장 흔한 구멍들을 막아 줍니다.

## ② 환경변수 — 비밀은 코드에 적지 않는다

### 흔한 사고 이야기

한 개발자가 급한 마음에 **API 키를 코드에 그대로 적어** GitHub 에 올렸습니다.
"잠깐인데 뭐 어때."

그런데 **몇 분 만에** 자동 프로그램(봇)이 그 키를 찾아 훔쳐 갔고, 그 키로 클라우드에서 비싼 작업을 잔뜩 돌려 며칠 뒤 **수백만 원짜리 청구서**가 날아왔습니다.

과장이 아닙니다. 2025년 한 해 공개 GitHub 에 유출된 비밀키·비밀번호가 **약 2,865만 개**(전년 대비 34% 증가)로 역대 최대였고, **AI 서비스 키 유출은 1년 새 81% 급증**했습니다.

### 해결책 — 비밀값을 코드 밖에 두기

```
❌ 나쁜 예 (코드에 그대로 박아 넣음)
   apiKey = "sk-a1b2c3d4e5f6..."     ← 올리는 순간 유출

✅ 좋은 예 (코드는 '불러오기'만)
   apiKey = 환경변수에서 불러오기      ← 실제 값은 코드 밖 .env 파일에
   (그리고 .env 는 .gitignore 로 깃에 안 올라가게 막아 둠)
```

한 줄 요약입니다.

> **코드 = 공개해도 되는 것 / 환경변수 = 절대 공개하면 안 되는 것**

### 💬 AI에게 이렇게 말하세요

> "**API 키와 DB 접속 정보는 코드에 넣지 말고 환경변수로 빼줘.**
> `.env` 파일은 깃에 안 올라가게 해줘."

## ③ 인증 vs 인가 — 콘서트장 비유

로그인 기능에는 사실 **두 단계**가 숨어 있습니다.

| | 콘서트장으로 치면 | 묻는 것 | 실패하면 |
|---|---|---|---|
| **인증**(Authentication) | 입구의 **표 검사원** | "당신, 표 주인 맞아요?" | **401** — "누구세요?" |
| **인가**(Authorization) | VIP 구역의 **바운서** | "들어는 왔는데, 이 방에 들어갈 **권한**은 있어요?" | **403** — "안 돼요" |

로그인에 성공하면 서버가 **토큰**을 줍니다. 토큰은 **클럽 입구에서 받는 손목 밴드** 같은 것입니다 — 한 번 확인받고 밴드를 차면, 이후엔 매번 신분증을 안 보여줘도 밴드만 보이면 통과되죠.

### 비밀번호는 왜 '해시'로 저장하나

**해시** 는 비밀번호를 **되돌릴 수 없는 지문**으로 바꾸는 것입니다.

> 달걀을 **프라이**로 만들 수는 있어도, 프라이를 다시 **달걀**로 되돌릴 수는 없습니다.

서버는 원문 대신 **지문만** 저장하고, 로그인할 때 지문끼리 비교합니다. 그래서 데이터가 새어도 비밀번호 원문은 안전합니다.

**그런데 문제가 하나 있습니다.** 사람들이 흔히 쓰는 비밀번호(`123456`)는 지문도 뻔합니다. 그래서 **솔트(salt)** — **사람마다 다른 무작위 값** — 를 섞어 지문을 냅니다. 같은 `123456`이라도 사람마다 지문이 달라지죠.

그리고 좋은 서비스는 **bcrypt** 같은 **일부러 느리게 계산되는** 방식을 씁니다. **느린 게 장점**입니다 — 도둑이 수억 개를 대입해 보기 어려워지니까요.

### 💬 AI에게 이렇게 말하세요

> "**비밀번호는 솔트를 섞어 bcrypt 로 해시해서 저장해줘.**"
> 그리고 만든 뒤 되물으세요 — "**내 데이터를 남이 보면 안 되는데, 권한 확인(인가)이 되어 있나?**"

## 곁들여 — 쿠키와 세션 (웹은 원래 건망증이 심하다)

로그인 한 번 하면 페이지를 넘겨도 유지되죠. 당연해 보이지만 **원래 웹은 기억력이 없습니다.** 초창기 HTTP 는 요청 하나하나를 **매번 처음 보는 손님**처럼 취급했습니다. 그대로라면 로그인하고 다음 페이지로 가는 순간 로그아웃될 겁니다.

이 건망증을 고치려고 나온 것이 **쿠키**와 **세션**입니다.

| | 비유 | 하는 일 |
|---|---|---|
| **쿠키** | 내 **지갑 속 작은 카드** | 사이트가 번호를 적어 주면 브라우저가 보관했다가 방문할 때마다 보여 줌 |
| **세션** | 사이트 **금고 속 내 서류철** | 카드의 번호를 보고 "아, 이 사람!" 하며 내 정보를 꺼냄 |

흐름은 이렇습니다.
① 로그인 → 서버가 세션을 만들고 **고유 번호** 발급 → ② 그 번호를 **쿠키**로 브라우저에 줌 → ③ 이후 요청마다 브라우저가 쿠키를 함께 보냄 → ④ 서버가 번호로 나를 알아봄.

> ⚠️ **진짜 정보는 브라우저에 두면 안 됩니다.** 쿠키는 사용자가 조작할 수 있어서 `이름=일반사용자` 를 `이름=관리자` 로 바꾸는 장난이 가능하거든요.
> 그래서 **브라우저엔 의미 없는 번호만, 진짜 정보는 서버 금고에** 둡니다.

('로그인 유지' 체크박스는 이 카드를 더 오래 보관하는 것입니다.)

## 4강 자가 점검 — 이 습관, 안전할까?

| 습관 | 안전? | 왜 |
|---|---|---|
| API 키를 코드에 적어 GitHub 에 올린다 | ❌ | 유출 — **환경변수**로 빼야 |
| 사용자가 입력한 값을 그대로 믿고 처리한다 | ❌ | **주입 공격**이 들어오는 문 |
| 비밀번호를 솔트 섞어 해시로 저장한다 | ⭕ | 좋습니다 |
| 모든 사이트에 같은 비밀번호를 쓴다 | ❌ | 한 곳 털리면 다 위험 (마이스페이스의 교훈) |
| 로그인 뒤 '권한(인가)'까지 확인한다 | ⭕ | 인증 **+** 인가 |

### 🎯 4강에서 내가 할 일

> **AI는 아주 빠른 신입 개발자**입니다. 속도는 놀랍지만 **보안·비밀 관리·권한 확인은 감독이 필요**합니다.
> 신입에게 "결제 로직을 알아서 안전하게 짜 둬"라고 방치하지 않듯이요.
> **입력 검증 · 비밀은 환경변수 · 권한 확인(+비밀번호 해시)** — 이 셋을 프롬프트로 요구하고, 결과를 한 번 더 되묻는 것.

# 5강. 배포 — 세상에 내보내기

## 배포가 뭔가

**배포(deploy)** 는 **내 컴퓨터에만 있던 서비스를 늘 켜진 서버에 올려, 누구나 주소로 들어올 수 있게** 하는 것입니다.

예전엔 서버 사고 설정하느라 **며칠씩 걸리던 전문가의 일**이었습니다. 지금은 비전공자도 **클릭 몇 번 + AI의 도움**으로 몇 분이면 됩니다.

## 어디에 올리나 — 셋으로 나눠 올린다 (식당 비유)

| 무엇을 | 어디에 (예) | 식당으로 치면 | 왜 여기에? |
|---|---|---|---|
| **화면** (프론트) | Vercel · Netlify | 전 세계 여러 지점의 **홀** | 손님 가까운 곳에서 빠르게 보여줘야 |
| **서버** (백엔드) | Render · Railway | 늘 켜진 **주방** | 요청을 계속 처리해야 |
| **데이터** (DB) | Supabase 등 | 관리형 **재료 창고** | 안전하게 보관해야 |

**"왜 한 군데에 다 안 올려요?"** → **각자 잘하는 게 다르기 때문**입니다. 화면 전문점은 전 세계에 빠르게 뿌리는 데 강하고, 서버 전문점은 오래 돌아가는 데 강하고, 데이터 전문점은 안전한 보관에 강합니다.

> 💡 무료로 시작한다면 서버는 **Render** 가 무난합니다. Railway 는 시작 크레딧을 다 쓰면 유료로 넘어갑니다.

## GitHub 에 올리면 자동으로 배포됩니다

1. 내 코드를 **GitHub**(코드 저장소)에 올린다
2. 배포 플랫폼(Vercel 등)에서 **"이 GitHub 저장소와 연결"** 버튼을 누른다
3. 그때부터 플랫폼이 저장소를 지켜보다가, **코드가 바뀔 때마다 자동으로 다시 배포**한다
4. 배포가 끝나면 **주소**를 하나 만들어 준다 (예: `내프로젝트.vercel.app`)

즉 **"저장 → 올리기 → 자동 배포"** 가 한 줄로 이어집니다. 한 번 연결해 두면 다음부터는 코드를 고치고 저장하기만 해도 세상에 반영됩니다.

> 그리고 이 순간 — **어젯밤 친구에게 보냈지만 안 열리던 그 링크**가, 이제 어디서든 열립니다.

## 초보가 가장 많이 막히는 세 곳

**① 환경변수 빼먹기** — 내 컴퓨터의 `.env`(비밀값)는 GitHub 에 **일부러 안 올립니다**(올리면 유출이니까). 그래서 **배포 플랫폼의 설정 화면에 비밀값을 따로 넣어 줘야** 합니다.
→ 이걸 빼먹어서 **"로컬에선 됐는데 배포하니 안 돼"** 가 가장 많습니다.

**② CORS 막힘** — 화면(Vercel)과 서버(Railway)가 **서로 다른 주소**에 살면, 서버가 "이 화면에서 오는 요청은 허용"이라고 문을 열어 줘야 합니다. 안 그러면 브라우저가 **"다른 집 요청은 못 받아"** 라며 막습니다.
→ AI에게 *"내 프론트 주소에서 오는 요청을 허용(CORS)해줘"* 라고 하면 됩니다.

**③ 무료의 함정** — 대부분 무료 티어가 있지만 **트래픽이 늘면 유료로 넘어갑니다.**

## 요금 폭탄 피하기

무료로 시작해도 방심하면 요금이 훅 올라갈 수 있습니다. 특히 **키 유출**이나 실수로 만든 **무한 반복** 때문에요. 세 가지만 지키면 됩니다.

1. **요금 알림을 켜 둔다** — "한 달에 X원 넘으면 알려줘"
2. **한도를 안다** — 내가 쓰는 플랫폼의 무료 한도가 얼마인지 확인
3. **비밀 키를 지킨다** — 유출된 키로 남이 비싼 작업을 돌리면 **그 요금은 내 몫**

> 겁주려는 게 아닙니다. **알고 시작하면 거의 다 예방 가능한 것들**입니다.

### 🎯 5강에서 내가 할 일 — AI에게 줄 프롬프트

> 이 프로젝트를 배포하고 싶어. 비용은 최소로 하고 싶어.
> 1. 프론트엔드와 백엔드를 각각 어디에 올리면 좋을지 **무료 옵션**으로 추천해줘.
> 2. GitHub 에 올리고 **자동 배포**되게 하는 순서를 하나씩 알려줘.
> 3. **비밀 키(환경변수)** 는 어디에 어떻게 넣어야 하는지 짚어줘.
> 4. 배포 후 화면이 서버와 통신이 안 될 때 확인할 것(**CORS·환경변수**)을 체크리스트로 줘.
> 5. **요금이 갑자기 오르지 않게** 설정할 것이 있으면 알려줘.

# 6강. 무료 서버 고르기

## 먼저 알아 둘 흐름 — 공짜의 세계는 줄어드는 중

| 서비스 | 언제 | 무슨 일 |
|---|---|---|
| **Heroku** | 2022년 11월 | 한때 초보들의 성지였던 무료 서버가 **완전히 사라짐** |
| **Railway** | 2023년 | 상시 무료 없앰 |
| **Fly.io** | 2024년 | 상시 무료 없앰 |
| **Glitch** | 2025년 7월 | 앱 호스팅 종료 |

**왜일까요?** 무료 계정을 **암호화폐 채굴** 같은 곳에 악용하는 사람이 늘면서 회사들이 공짜를 거둬들인 겁니다.

> 그러니 **"지금 무료인 것도 언젠가 바뀔 수 있다"** 는 전제로, **가입 직전에 공식 요금 페이지를 한 번 확인**하는 습관이 안전합니다.

## 용어 두 개만

- **정적 사이트** = 화면만 있는 것 (포트폴리오·소개 페이지)
- **백엔드** = 뒤에서 데이터를 처리하는 부분

## 지금 쓸 만한 무료 호스팅 (2026년 기준)

| 서비스 | 뭘 올리기 좋나 | 무료로 주는 것 · 주의점 | 카드 |
|---|---|---|---|
| **Cloudflare Pages** | 정적·프론트 | 대역폭 **무제한** — 트래픽 걱정이 가장 적음 | 불필요 |
| **GitHub Pages** | 정적 전용 | 가장 단순. 코드 저장하던 곳에 그대로 게시 | 불필요 |
| **Vercel** (Hobby) | 프론트·Next.js | 손이 가장 덜 감. 단 **개인·비상업용만** | 불필요 |
| **Netlify** | 정적·프론트 | Vercel 대안, **상업적 이용 허용** | 불필요 |
| **Render** | 백엔드 API | **15분 안 쓰면 잠듦** (깨는 데 ~1분) | 불필요 |
| **Supabase** | 백엔드+DB | DB·로그인 한 번에. **7일 미사용 시 일시정지** | 불필요 |
| **Oracle Always Free** | 진짜 리눅스 서버 | 상시 무료 VM. 단 **카드 필요·설정 어려움** | 필요 |

## 이럴 땐 이걸로 시작

| 내가 만든 게 | 시작할 곳 |
|---|---|
| 포트폴리오·소개 페이지 (화면만) | **Cloudflare Pages** 또는 **GitHub Pages** |
| 프레임워크로 만든 프론트 (Next.js 등) | **Vercel** (수익 내는 서비스라면 나중에 유료로) |
| 로그인·저장이 필요한 백엔드+DB | **Supabase** 가 1순위, API 서버가 따로 필요하면 **Render** 곁들이기 |
| 진짜 서버를 만져 보며 공부 | **Oracle Always Free** (설정 난이도 있음) |

## 무료 티어의 함정 세 가지

**① 잠듦(spin-down)** — 무료 백엔드는 한동안 아무도 안 오면 잠듭니다. 오랜만의 첫 방문자는 화면이 뜨는 데 **1분쯤** 걸릴 수 있어요. **고장이 아닙니다.** Render 무료가 대표적입니다.

**② 기한·일시정지** — 무료 DB 가 일정 기간 뒤 사라지거나(Render 무료 Postgres 는 30일 후 만료), 안 쓰면 잠시 멈추는(Supabase 7일) 경우가 있습니다.
→ **중요한 데이터는 백업을 꼭 따로 받아 두세요.**

**③ 요금 폭탄** — 카드가 걸린 서비스는 **예산 알림·상한**을 걸어 두세요.

### 🎯 6강에서 내가 할 일

> **무료는 "배우고 시연하기"엔 충분합니다.**
> "많은 사람에게 안정적으로 24시간 제공"하는 단계가 오면, 그때 유료를 검토하면 됩니다.

# 부록. 어려운 말 → 쉬운 말 사전

| 어려운 말 | 쉬운 말 | 한 문장 |
|---|---|---|
| 배포(deploy) | **세상에 내놓기** | 내 컴퓨터 속 서비스를 누구나 열 수 있는 주소로 만드는 것 |
| 프론트엔드 | **화면** | 손님 눈에 보이는 홀 |
| 백엔드 | **뒤편·주방** | 눈에 안 보이는 곳에서 요청을 처리하는 부분 |
| 환경변수 | **코드 밖에 둔 비밀값** | API 키·비밀번호를 코드에 안 적고 따로 보관 |
| `.env` | **비밀값 적어 두는 파일** | 깃에 절대 안 올리는 파일 |
| 인증(Authentication) | **표 검사** | "당신 맞아요?" — 로그인 확인 |
| 인가(Authorization) | **권한 확인** | "이 방에 들어갈 자격 있어요?" |
| 토큰 | **손목 밴드** | 한 번 확인받고 차면 이후엔 이것만 보여주면 통과 |
| 해시(hash) | **되돌릴 수 없는 지문** | 프라이는 달걀로 못 되돌린다 |
| 솔트(salt) | **사람마다 다른 무작위 값** | 같은 비밀번호라도 지문이 달라지게 |
| bcrypt | **일부러 느린 지문 계산법** | 느려서 도둑이 대입해 보기 어렵다 |
| 쿠키 | **지갑 속 작은 카드** | 브라우저가 보관했다 매번 보여주는 번호 |
| 세션 | **금고 속 내 서류철** | 서버가 번호를 보고 꺼내는 진짜 정보 |
| 무상태(stateless) | **건망증** | 요청 하나하나를 매번 처음 보는 손님처럼 취급 |
| CORS | **다른 집 요청 허용 여부** | 화면과 서버 주소가 다르면 서버가 문을 열어줘야 |
| 정적 사이트 | **화면만 있는 것** | 포트폴리오·소개 페이지 |
| 무료 티어 | **공짜 요금제** | 배우고 시연하기엔 충분, 큰 운영엔 부족 |
| 스핀다운(spin-down) | **잠듦** | 한동안 아무도 안 오면 서버가 잠, 첫 방문에 1분쯤 |
| 401 | **"누구세요?"** | 로그인이 안 된 상태 |
| 403 | **"안 돼요"** | 로그인은 했는데 권한이 없는 상태 |

# 세 강의를 한 장으로

| | 핵심 한 문장 | 내가 할 행동 |
|---|---|---|
| **4강** | AI는 돌아가는 코드는 잘 만들지만 안전한 코드는 놓친다 | **입력 검증 · 비밀은 환경변수 · 권한 확인**을 프롬프트로 요구하고 되묻기 |
| **5강** | 화면·서버·데이터를 각자 잘하는 곳에 나눠 올리고 GitHub 로 자동 배포 | 배포 플랫폼에 **환경변수 따로 넣기**, **CORS 열어주기**, **요금 알림 켜기** |
| **6강** | 무료는 배우고 시연하기엔 충분, 다만 공짜의 세계는 줄어드는 중 | **가입 직전 공식 요금 페이지 확인**, 잠듦·기한·요금 폭탄 세 함정 인지 |

> **전체를 관통하는 한 문장**
> 오늘 배운 건 코드가 아니라 **AI에게 무엇을 요구해야 하는지**입니다.
> 비전공자가 할 수 있는 가장 강력한 품질 관리는 **요구하고, 결과를 한 번 더 되묻는 것**입니다.
