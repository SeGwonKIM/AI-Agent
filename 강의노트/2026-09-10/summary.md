# 2026-09-10 — 인공지능은 어떻게 "배우는가"

7개 강의. 회귀 → 분류 → 파인튜닝을 직접 돌려 보며 "학습"의 정체를 확인하고,
마지막에 **모델보다 데이터가 결과를 가른다**는 결론으로 모인다.

## 1. 규칙을 짜는 기계에서 배우는 기계로

**인공지능 ⊃ 머신러닝 ⊃ 딥러닝** 의 포개진 구조. 요즘 화제인 생성형 AI는 딥러닝 위에 선다.

**왜 규칙을 직접 안 짜나** — 예외가 예외를 부르기 때문이다.

- "귀가 뾰족하면 고양이" → 폴드귀 고양이가 반례
- "수염이 있으면 고양이" → 개도 수염이 있다
- 스팸 필터에서 '무료'를 막으면 '무 료', '당.첨' 으로 빠져나간다

그래서 방향을 뒤집는다. **규칙을 사람이 적는 대신, 예시를 잔뜩 주고 기계가 규칙을 찾게 한다.**

### 학습 = 네 칸짜리 고리

```
데이터 → 예측 → 오차 계산 → 가중치 조정 → (반복)
```

5를 예측했는데 정답이 7이면 오차 +2. 이 오차를 줄이는 방향으로 숫자를 조금씩 민다.
오차를 언덕으로 보면 가장 낮은 골짜기로 한 걸음씩 내려가는 것 — **경사하강(gradient descent)**.

### 계보

| 연도 | 사람 | 한 일 |
|---|---|---|
| 1951 | 클로드 섀넌 | 다음 글자 맞히기 실험. 언어는 통계적으로 예측 가능하다 |
| 1958 | 프랭크 로젠블랫 | 퍼셉트론. "틀리면 틀린 만큼 가중치를 고친다" |
| 1959 | 아서 새뮤얼 | "명시적으로 프로그래밍하지 않고 배우게 하는 연구" |
| 1986 | 러멜하트·힌턴·윌리엄스 | **역전파**. 여러 겹에서도 "네가 오차에 얼마나 기여했나"를 되짚어 준다 |

로젠블랫의 모델은 한 겹뿐이라 복잡한 패턴을 못 배웠고, 역전파가 그 한계를 풀었다.
**오늘날 GPT를 포함한 거의 모든 신경망이 이 방식으로 학습한다.**

### 학습의 결과물은 규칙집이 아니다

**파라미터에 압축된 패턴**이다. 여기서 "외운다"와 "일반화한다"가 갈린다.
일반화는 어디까지나 추정이라 — **모델은 자신 있게 틀릴 수 있다.**

오늘 셋 다 정답이 달린 예시로 배우는 **지도학습**이다.

## 2. 데이터를 숫자로 바꾸기

기계가 만질 수 있는 건 **오직 숫자뿐**이다. 그래서 첫 단계는 언제나 숫자로 바꾸기.

**글** — 문장을 의미 단위인 **토큰**으로 자르고, 각 토큰을 숫자 묶음인 **벡터**로 바꾼다.
비슷한 맥락에서 쓰이는 단어일수록 비슷한 벡터가 되게 맞춘 것이 **임베딩**.
"이웃을 보면 그 단어의 뜻을 안다."

**그림** — 사진은 픽셀 격자이고 각 점은 밝기 숫자다. MNIST 한 장 = 28×28 = **784개 숫자**.

### 텐서 사다리

| 차수 | 이름 | 예 |
|---|---|---|
| 0차 | 스칼라 | 매출 `7` |
| 1차 | 벡터 | `[방문객, 요일, 날씨]` |
| 2차 | 행렬 | 흑백 사진 (세로×가로) |
| 3차↑ | 텐서 | 컬러 사진 (높이×너비×3), 배치면 한 차원 더 |

### 비슷함을 재는 두 가지

- **거리** — 두 점이 얼마나 붙어 있나. A=(2,3)과 B=(2,4)는 가깝다
- **방향(각도)** — 크기는 달라도 같은 쪽을 가리키면 "결이 같다"

핵심: **점의 절대 위치가 아니라 점들 사이의 관계가 뜻을 만든다.**

### 신경망 한 층 = 세 박자

```
곱하고(W) → 더하고(b) → 비틀기(활성화 함수)
```

`Wx + b` 가 전부다. 가중치는 "이 입력이 얼마나 중요한가", 편향은 저울의 영점.

**왜 비트나** — 직선 위에 직선을 아무리 얹어도 직선이다. 층을 쌓아도 전체가 하나의 직선으로
뭉개진다. 그래서 층마다 끝에 꺾임을 넣는다. **ReLU** 는 음수를 0으로 누르고 양수는 통과시킨다.
이 작은 꺾임 하나가 곡선을 그릴 줄 아는 모델로 바꾼다.

**계산 예** — x=[2,1], W=[0.5,-1], b=0.2 → 2×0.5 + 1×(-1) + 0.2 = 0.2 → ReLU 통과 0.2
→ 다음 층 W₂=3, b₂=-0.1 → ReLU(3×0.2 − 0.1) = **0.5**

## 3. 가장 작은 학습을 코드로 (회귀)

파라미터가 **weight 1개, bias 1개**뿐인 모델로 "학습"을 눈으로 확인한다.

**상황** — 카페 30일치 (방문객, 매출) 기록. 숨은 규칙은 `매출 = 2 × 방문객 + 1` 에 잡음을 섞은 것.
모델은 이 규칙을 **모른 채** 0에서 출발한다.

### torch에서 알아야 할 두 가지

- **텐서** — 숫자 배열. 같은 코드가 CPU에서도 GPU에서도 돈다 (device만 바꾸면 됨)
- **autograd** — `loss.backward()` 한 줄로 "각 파라미터가 오차에 얼마나 기여했나"(기울기)를 자동 계산.
  역전파를 torch가 대신 밟아 준다

### 핵심 루프

```python
pred = model(x)                    # 예측
loss = ((pred - y) ** 2).mean()    # 오차 (평균제곱오차 MSE)
loss.backward()                    # 기울기 계산 (역전파)
w -= lr * w.grad                   # 기울기 반대 방향으로 한 걸음 (경사하강)
b -= lr * b.grad
```

**결과** — `매출 = 2.07 × 방문객 + 0.79` (숨은 정답 2.00, 1.00).
아무도 안 알려줬는데 데이터 30개만 보고 찾아냈다.

**절편이 더 흔들리는 이유** — 절편은 방문객 0명 지점의 값인데, 데이터 중심에서 멀리 떨어진
지점이라 잡음에 더 민감하다.

**LLM도 다르지 않다.** 다른 건 오직 규모 — 파라미터가 2개가 아니라 수천억 개이고,
예측하는 것이 숫자 하나가 아니라 다음 토큰의 확률분포일 뿐.
이 작은 학습을 웹 전체 규모로 돌린 것이 **사전학습(pretraining)**.

## 4. softmax와 MNIST (분류)

카페는 연속된 숫자를 맞히는 **회귀**. 세상 많은 문제는 "어느 쪽인가"를 고르는 **분류**.

분류의 출력은 정답 하나가 아니라 **후보마다 매긴 확률**이다.
"3일 확률 88%, 8일 확률 9%…" 이렇게 점수를 합이 1인 확률로 바꿔 주는 장치가 **softmax**.

### softmax 계산

```
로짓(raw 점수) : [2.0, 1.0, 0.1]
① exp 적용      : [7.39, 2.72, 1.11]   (모두 양수로, 차이는 더 벌려서)
② 합(11.2)으로 나눔 : [0.66, 0.24, 0.10]  (합 = 1)
```

**왜 이름이 softmax인가** — 그냥 max는 가장 큰 하나만 1, 나머지 0으로 딱 자른다(hard).
softmax는 나머지에도 확률을 조금씩 남겨 부드럽게(soft) 고른다.

**확률값 자체가 "얼마나 확신하는지"** 다. 0.66이면 애매하고 0.99면 강한 확신.
그래서 "확률이 낮으면 사람에게 넘긴다" 같은 기준을 세울 수 있다.

**언어모델과 같은 장치다.** LLM은 다음 토큰 후보 수만 개에, 숫자 분류기는 0~9 열 개에
확률을 매길 뿐 원리는 같다.

**MNIST** — 손글씨 숫자 7만 장. 기계학습의 "Hello World".

**주의** — 출력층에 softmax를 얹고 `CrossEntropyLoss` 를 또 쓰면 **이중 적용**이 된다.
softmax는 예측을 보여줄 때만 적용한다.

**관찰 결과** — 전체 데이터로 96%대(구성·시간 늘리면 98%대). **데이터를 10%로 줄이면 정확도가 떨어진다.**
모델이 나빠져서가 아니라 **볼 예시가 줄었기 때문**이다.

## 5. 파인튜닝 — 남이 배운 것을 물려받기

개/고양이 구분에는 귀·털·눈·질감 같은 복잡한 시각 특징이 필요한데, 밑바닥부터 배우려면
엄청난 사진과 계산이 든다. 우리에겐 몇백 장뿐일 수도 있다.

**그래서 남이 이미 배운 것을 물려받는다.** 수백만 장으로 미리 학습된 모델(ResNet18 — 18은 층 수)은
이미 "선·모서리·질감·형태"를 보는 눈을 갖고 있다. 그 눈은 그대로 두고 **마지막 판단 부분만**
내 문제에 맞게 더 학습시키는 것이 **파인튜닝**, 넓게는 **전이학습**.

### 무엇이 전이되나

층을 지날수록 점점 복잡한 것을 본다.

- **앞쪽 층** — 선·모서리·색 같은 **보편적** 패턴 → 개든 고양이든 자동차든 똑같이 쓸모 있다
- **뒤쪽 층** — 눈·귀·질감 같은 **구체적** 형태

그래서 앞쪽 층은 **얼려 두고(freeze)** 뒤쪽 판단 층부터만 새로 배운다.

**관찰 포인트** — 데이터가 적을 때 사전학습 쪽이 밑바닥 학습보다 **크게** 앞선다.

## 6. 왜 내 노트북으론 벅찰까

| 오늘의 학습 | 파라미터 | 어디서 도나 |
|---|---|---|
| 카페 선형모델 | **2개** (w, b) | 노트북에서 즉시 |
| MNIST 분류기 | 수만 ~ 수십만 | 노트북 CPU로 몇 분 |
| ResNet18 파인튜닝 | 약 **1,100만** | GPU 권장 (Colab 등) |
| 대형 언어모델 | 수십억 ~ **수천억** | GPU 수백~수천 대, 데이터센터 |

학습 계산의 대부분은 **방대한 행렬 곱셈**이다. 파라미터와 데이터가 늘수록 곱셈이 폭발한다.

**왜 GPU인가** — CPU는 복잡한 일을 순서대로 처리하는 코어가 소수, GPU는 단순 계산을
동시에 처리하는 코어가 **수천 개**. 행렬 곱셈 속 곱셈들은 서로 독립이라 순서 없이 한꺼번에
계산할 수 있어 GPU에 딱 맞는다. 수십~수백 배 빠르다.

**규모 감각** — LLM의 수천억 파라미터를 1초에 하나씩 세기만 해도 **수천 년**이 걸린다.
LLM 사전학습은 고성능 GPU 수천 대를 수 주간 돌리고 수백만~수억 달러가 든다.

**그래서 현실의 실무는 직접 훈련하지 않는다.** 이미 학습된 모델을 파인튜닝하거나 API로 부른다.

### Colab CLI (2026년 6월 등장)

브라우저 탭 없이 명령어로 Colab GPU를 쓴다. 공식 패키지 `google-colab-cli`.

```bash
pip install google-colab-cli
colab run --gpu T4 train.py    # GPU VM 띄움 → 실행 → 자동 반납
```

무료는 보통 T4, A100·H100·TPU는 유료(Pro/Pro+).

**AI 에이전트가 직접 쓰도록 설계됐다.** Claude Code 같은 코딩 에이전트가 이 명령을 대신 실행할 수 있어,
"에이전트에게 시킨다"가 말뿐이 아니라 실제 GPU에서 코드를 돌려 정확도를 받아오는 데까지 이어진다.

## 7. 결국 데이터가 전부다

오늘 학습을 세 번 봤다.

| | 무엇을 예측 | 방법 |
|---|---|---|
| **회귀** (카페 매출) | 연속된 숫자 | 예측 → 오차 → 조정으로 직선을 찾음 |
| **분류** (MNIST) | 어느 범주인지 | softmax로 후보마다 확률을 매겨 고름 |
| **파인튜닝** (개/고양이) | 어느 범주인지 | 사전학습된 특징을 물려받아 적은 데이터로 맞춤 |

**셋을 관통하는 한 문장 — 모델 구조보다 데이터가 결과를 가른다.**

데이터를 10%로 줄이면 정확도가 떨어졌고, 사전학습된 특징을 물려받으면 적은 데이터로도 잘 됐다.
그래서 AI를 다루는 사람의 진짜 일은 **"좋은 모델 고르기"보다 좋은 데이터를 모으고 검증하는 것**에 가깝다.

앞으로 직접 학습을 돌릴 일은 많지 않다. 하지만 원리를 봤기에 코딩 에이전트에게
**무엇을 시키고**(무슨 데이터로, 어떤 학습을) **결과의 무엇을 의심할지**(데이터가 충분한가,
정확도가 왜 이런가) 판단할 수 있다.

### 핵심 정리

| 질문 | 답 |
|---|---|
| AI가 "배운다"는 건? | 규칙을 손으로 짜는 대신, 데이터에서 예측 → 오차 → 조정을 반복해 패턴을 찾는 것 |
| 회귀와 분류의 차이? | 회귀는 연속된 값, 분류는 어느 범주인지(softmax 확률로) |
| softmax는? | 여러 후보 점수를 합이 1인 확률로 바꿔, 확신 정도와 함께 하나를 고르게 함 |
| 파인튜닝은 왜? | 사전학습된 특징을 물려받아 적은 데이터·계산으로 내 문제에 맞추려고 |
| 왜 GPU? | 학습은 방대한 행렬 곱셈이고, GPU는 이를 대규모 병렬로 처리 |
| AI 활용가의 진짜 일? | 모델 고르기보다, 좋은 데이터를 모으고 결과를 의심·검증하는 것 |
